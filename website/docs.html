Ecosystem Architecture

YodaMan is organized around one shared local runtime used by the web UI, desktop app, VS Code extension, mobile companion, and CLI.

  • Runtime owns agent execution, tools, indexing, sessions, plugins, audit, and safety policy.
  • Clients own UX: editor actions, desktop control, mobile approvals, and notifications.
  • REST and SSE provide the current protocol; WebSocket subscriptions are a future upgrade.

Security And Audit

The runtime includes baseline hardening for local agent tools.

  • Workspace-scoped file and command paths.
  • Blocked high-risk shell command patterns.
  • Audit log entries for tool calls.
  • Optional pairing-token enforcement for non-local clients.

Mobile Linking

The phone must connect to the Mac's LAN address, not 127.0.0.1.

curl -X POST http://127.0.0.1:3090/api/pairing \
  -H "Content-Type: application/json" \
  -d '{"runtimeUrl":"http://YOUR-MAC-LAN-IP:3090"}'

Paste the returned yodaman://pair deep link into the mobile app and tap Use Pairing Link.

Publishing

The VS Code extension packages with vsce. The mobile app uses Expo EAS for Google Play App Bundle builds and submission.

cd extensions/vscode-yodaman
npm run package

cd apps/mobile
npm run build:android

Actual publishing requires Marketplace, Expo, and Google Play credentials.

API Reference

Important runtime endpoints include:

  • POST /api/agent/task
  • GET /api/agent/tasks
  • GET /api/agent/tasks/:taskId/events
  • GET /api/agent/pending-approvals
  • GET /api/policy
  • GET /api/audit
  • POST /api/pairing

Desktop App

The Electron app packages the existing React UI and starts the Node runtime as a managed sidecar when needed.

npm run desktop
npm run desktop:pack
