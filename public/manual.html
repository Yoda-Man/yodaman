YodaMan Manual

Local-first workspace intelligence with supervised agent automation across web, desktop, VS Code, and mobile clients.

Version 0.1.7

1. Setup

Install Context Expert, then install and start YodaMan from the project root.

npm install -g @contextexpert/cli
npm install
sh setup.sh
npm start

The backend runtime listens on http://localhost:3090. The development web UI listens on http://localhost:5190.

2. Core Ideas

Local-first intelligence

Project context starts from local watched directories and is reused by chat, search, agent tasks, and external clients.

SQLite Persistence

Task history and audit logs persist locally in SQLite database (yodaman.db), falling back to JSON files if Node SQLite is unsupported.

System Tray Controls

Electron desktop app runs a system tray daemon allowing you to show/hide the app, copy pairing links, restart background daemon, or quit.

Restricted plugins

Uploaded plugins must declare permissions. Unrestricted plugins are blocked unless explicitly allowed by environment variable.

3. Web UI

  • Projects: Add watched folders, select workspaces, and queue reindexing.
  • Chat: Ask questions about indexed project context.
  • Search: Run semantic search across all projects or the selected project.
  • Dashboard: View runtime diagnostics, task counts, pending approvals, and create mobile pairing links.
  • Plugins: Install JavaScript plugins and inspect declared permissions.

4. Agent Tasks

Recent task state and events persist in SQLite database (or task-history.json), so task timelines survive runtime restarts. Clients can inspect task starts, tool events, approval requests, cancellations, final answers, and errors.

When a write needs approval, clients show the proposal, send your approval or rejection, and the agent continues with that decision.

You can purge histories and audit trails directly from the UI or sidebar actions: Clear Task History (sends DELETE /api/agent/tasks) and Clear Audit Logs (sends DELETE /api/audit).

5. Desktop App

Run npm run desktop to launch the Electron shell. The desktop app starts the backend as a managed sidecar when no runtime is already available.

  • Restart Managed Runtime restarts Electron-managed sidecars.
  • Copy Mobile Pairing Link creates and copies a yodaman://pair link.
  • Add Project Folder opens a native folder picker and registers the selected workspace.

The desktop app shows native notifications when a task needs approval or completes, and manages app persistence via System Tray context options.

6. VS Code Extension

The extension checks runtime status, starts the configured runtime command, asks/searches/reindexes the current workspace, streams agent events, opens proposed writes as diffs, sends approve, reject, or cancel decisions, and features a hierarchical tree sidebar with commands to view task details or clear histories/audits.

7. Mobile Companion

The mobile app parses pairing links, checks status, lists projects, routes ask/search to a selected project, inspects task timelines and event details, cancels active tasks, and handles pending approvals.

8. Verification

npm test
npm run build
npm run release:smoke

9. Troubleshooting

  • Context Expert not found: Confirm ctx --version works.
  • Runtime unreachable: Check port 3090.
  • Web UI unreachable: Check port 5190 during development.
  • Mobile cannot connect: Use the desktop LAN IP and generate a fresh pairing link.
  • Plugin blocked: Add explicit permissions or intentionally allow unrestricted plugins.
