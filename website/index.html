The three-tool pillar

Three mandatory tools, blended into every answer

No silos, no optional features — this is the architecture. Each tool answers a different question, and YodaMan never consults one without the others.

Context Expert — meaning

Semantic search and LLM reasoning over your indexed workspace. Powers search, the agent finding files, and RAG retrieval.

Graphify — structure

The local knowledge graph. Powers blast radius, centrality, proximity, and the structural half of ranking.

OpenSpec — intent

Architecture specs as a first-class input. Powers spec coverage, drift detection, and the propose/validate/archive workflow.

Search ranks by all three: semantic × 0.50 + proximity × 0.20 + centrality × 0.15 + specCoverage × 0.15. The agent gets a Stardust Brief every turn with graph state, spec awareness, and per-file impact. Planning follows Propose → Validate → Archive with drift checking.

Stardust

Real-time Stardust dashboard + cross-tool composition

Context Expert, Graphify, and OpenSpec are all required — so YodaMan connects them. Each tool's output feeds the next instead of stopping at its own tab. The Stardust dashboard makes that connection visible across eight tabs — Board, Drift, Compose, Trust, Trace, Diagnostics, Commands, and Impact — with a live change board, spec diffs, and a WebSocket activity feed.

Live change board + spec diff

The Board tab is now a real-time OpenSpec dashboard. A card-based change board shows every active change with task progress, validation health, and live timestamps. Click any card to open a side-by-side spec diff with operation-grouped deltas (ADDED/MODIFIED/REMOVED/RENAMED) and a one-click validate/archive workflow.

Drift detection

The Drift tab compares current workspace state against active OpenSpec specs and flags every mismatch. Divergent files get severity badges, a side-by-side diff, and a one-click reindex action so you can close the gap before it grows.

File-centric cross-reference

The Compose tab answers: "what does every tool know about this file?" Enter any repo path to see which OpenSpec specs describe it, its Graphify structural position (dependents, centrality, blast radius, test coverage), and how Context Expert ranks it. Three columns, one file, no guesswork.

Trust that updates itself

The Trust tab shows per-tool health (Context Expert index freshness, Graphify graph state, OpenSpec CLI status) plus the overall WorkspaceReadiness verdict. A live activity feed tracks every file change in openspec/ pushed over WebSocket. Post-write reindex and regraph keep answers honest.

Search that explains itself

The Trace tab shows WHY each result ranked where it did. Every file gets four scores: semantic relevance from Context Expert, graph proximity to your active file, structural centrality from Graphify, and spec coverage from OpenSpec. The blend (0.50 + 0.20 + 0.15 + 0.15) is visible per result with colour-coded bars.

Runtime diagnostics

The Diagnostics tab surfaces runtime health at a glance. See Context Expert index freshness, Graphify graph state, OpenSpec CLI status, plugin health, and workspace connectivity in a single status grid with live WebSocket updates and colour-coded health badges.

Command audit trail

The Commands tab logs every tool execution with sanitized parameters, timing, exit codes, and result summaries. Filter by tool, status, or time range, and drill into any entry to see the full parameter payload and structured output.

Impact Analysis

Map the blast radius of any file change before you approve it. Set configurable hop depth (1–4), inspect affected dependents in a dual-panel Graphify graph + OpenSpec breakdown, review the risk verdict, and check per-file test coverage detail so you never merge blind.

Agent workflows

Give the agent useful power, then keep the keys in your hand

YodaMan can search, read, patch, write, list files, and execute commands inside allowed workspaces. Risky actions are visible through streamed events, approval prompts, and an audit log.

1 Ask about a workspace or assign a coding task
2 Agent searches context and calls approved tools
3 Proposed file changes wait for human review
4 Desktop, VS Code, or mobile can approve/reject

Local-first safety

Designed for private codebases

Workspace boundaries

File and command tools resolve paths against configured roots before they run.

Command policy

High-risk shell patterns are blocked by policy. Every file write pauses for a structured approval showing the diff, the files that depend on it, and whether any test covers the change.

Pairing tokens

Mobile clients can pair through a temporary token and deep link to the machine running YodaMan.

Audit logs

Tool calls are recorded with status, duration, sanitized parameters, and result summaries.

Install

Install from npm

1. Prerequisites

# Required — Context Expert (workspace indexing & search)
npm install -g @contextexpert/cli

# Required — OpenSpec (spec-driven development)
npm install -g @fission-ai/openspec@latest

# Required — Graphify (knowledge graphs)
python3 -m pip install graphifyy

# Required — Ollama (local LLM)
# Download from https://ollama.com
brew install ollama    # macOS
# or: curl -fsSL https://ollama.com/install.sh | sh  # Linux
# or: winget install Ollama.Ollama  # Windows

2. Install YodaMan

npm install -g yodaman

Start the runtime

yodaman

Open YodaMan
